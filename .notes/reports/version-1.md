## 5. Fidelity to mockup

What matches `.tasks/mockups/01.html`, what deviates and why.

Matches: dark zinc-950 shell, "Ash.cards" wordmark with accent dot, phone bottom tab bar (Home, Cards, Search) and laptop top bar with underline tabs, centred search and "2,138 cards · 121 sets"; home headline, large search, Recent chip row, Favourites carousel with "n pinned", Browse in three groups with the same tile/list/4-up set layouts and the "All 121 sets" link; gutterless 3→7 column grid with type-coloured 3 px frames and heart-on-tile; sticky chip row with the live count and Clear all; bottom sheet with rail, Reset and "Show n results", 400 px popover on laptop; detail hero with radial type gradient, back pill, title block, type pills, HP, subtypes, flavour text, underlined tabs coloured by type, attack rows with cost dots and big damage, legality pills, "Illus." line. Colours and copy are the mockup's.

Deviations:

1. "Recently viewed" row dropped: the frozen store holds only favourite ids and recent searches (settled 2.12), so there is no data for it.
2. Sort added as a fourth chip / rail section ("Collection order / Name / Set"): the mockup has no sort UI; it follows the existing chip and panel pattern.
3. Empty-state icon is the animate-ui ghost (settled 2.8 candidate spot) instead of the mockup's static Poké-ball outline.
4. zinc-500/600 text lifted to zinc-400 (`text-muted`) for axe contrast; the headline's "· 121 sets" stays zinc-500 (large bold text passes).
5. Phone search input and Filters button are fully round (`rounded-full`, h-9) instead of the mockup's `rounded-xl` h-10; the Filters badge is the same.
6. Favourites empty state is a dashed placeholder tile reserving the carousel height instead of the mockup's one-line text; this keeps the row height fixed.
7. Set names are set codes only (mockup also shows codes, so this matches the mockup but not settled 1.10's "content details").
8. Repeated ids are separate tiles with a ×N badge and "×N in collection" on the detail; the mockup's 19-card sample has no duplicates.
9. Tabs on the mockup are plain buttons; the build uses React Aria Tabs (roving focus, `aria-selected`).
10. Supertype pill for non-Pokémon cards (Trainer, Energy) and the resistances/retreat rows in Weaknesses are additions for real data the mockup sample lacks.

## 6. Known gaps

Numbered. What is missing or weak, in priority order.

Fixed in round 1 and verified by the reviewer: favicon 404, recent search on blur, heart fill under reduced motion, Apply with `replace`/no view transition. Fixed after the re-check (manager, verified with a Playwright script on the dev server, not re-reviewed): desktop popover is now `isNonModal`, so clicking another section chip switches the popover in one click and Escape still closes it; the trade-off is no focus trap inside the popover.

1. `app/src/components/CardSearchField.tsx`: the new blur rule records whatever draft is in the field when focus leaves, so an abandoned partial query ("ch") becomes a recent search; acceptable with the cap of 10, but a minimum length or recording only when the grid was actually viewed would keep the list cleaner.
2. `app/src/routes/card/Hero.tsx`: back link goes to plain `/cards`, losing the filters and query the user came from (known gap; `router.history.back()` when the previous entry is `/cards` would fix it).
3. `app/src/routes/cards/CardGrid.tsx`: all 2,138 tiles are in the DOM with 2 tab stops each (4,276) and there is no skip link; keyboard users cannot jump past the grid. Smoothness is fine thanks to `content-visibility: auto`.
4. Bundle: one 755 kB / 235 kB gzip chunk (motion, react-aria-components, router, query, zod) plus 233 kB gzip of `cards.json` on first load. The data file is frozen (settled 3.2 wanted a light first payload) but the app chunk could at least split `motion`/icons or the detail route.
5. `app/src/routes/home/RecentSearches.tsx`: `useStore.setState({ recentSearches: [] })` bypasses the store's actions because the frozen `store.ts` has no `clearRecentSearches`; add the action once the store can change.
6. `app/src/routes/cards/useIsDesktop.ts`: hardcodes `(min-width: 1024px)` separately from Tailwind's `lg`, and runs `window.matchMedia` at module load (breaks any non-browser import).
7. `byCount` is defined twice (`routes/home/Browse.tsx`, `routes/cards/FilterPanel.tsx`); the broken-image fallback is duplicated in `components/CardTile.tsx` and `routes/card/Hero.tsx`.
8. `app/src/shell/BottomNav.tsx`: focuses the search via `document.getElementById("cards-search")` after the navigate promise; it works today but couples the nav to a DOM id in another route.
9. `app/src/routes/card/DetailTabs.tsx`: content below the tab panel (the "Illus." line) moves 29 px when the pane height changes; a `min-h` on the panel would keep it still.
10. `test/cards.e2e.ts`, `test/home.e2e.ts`: axe excludes the grid in the two open-panel tests (speed, not a hidden violation: a full run with the panel open was clean); `page.locator(":focus")` is a CSS selector, borderline against testing rule 7. `/cards` axe takes ~26 s because of 2,138 tiles.
11. No README in the worktree yet (assignment deliverable 4); outside this build's scope but still missing.
