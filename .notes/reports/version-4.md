2. Bundle: one 788 kB / 246.8 kB gzip chunk, no route-level `lazy`/code splitting; plus the 1.57 MB raw (232,774 B ≈ 227 kB gzip, measured) `cards.json` on first load. Settled 3.2 "light first payload, full data in the background" is not implemented (data layer frozen before this build, so inherited).
3. Phone keyboard order: `Dock` renders after `main`, so from home the Cards link is 46 Tabs away and Search 47. Either render the dock before `main` in `Layout.tsx` or add the two links to the skip-link target.
4. `app/src/ui/hero.ts` is a mutable module singleton and `Pocket.tsx` writes `event.currentTarget.style.viewTransitionName` imperatively in `onClick`; works, but is state outside React and a senior reviewer will circle it. A `useState` in `CardsPage`/`FavouritesPage` or a router `state` field would do.
5. Fixed after review: `FavouritesPage` and `Splash` now import `PAGE_SIZE` from `data/paging.ts` and `Splash` uses `ui/Rings.tsx`. Still open: `useIsLaptop` hardcodes `(min-width: 1024px)` separately from Tailwind `lg:`.
6. Fixed after review: the home component is now `IndexSection`. Still open: `routes/root.tsx` + `routes/root/` is split differently from the other three route folders (`route.tsx` inside the folder).
7. `PageTurner` attaches a `window` keydown listener for ArrowLeft/Right/Home/End on every `/cards` render; it ignores inputs/dialogs but still fires while focus is on chips, sort trigger or dock, and every turn pushes history (Back walks pages). Acceptable for a binder, but worth a `replace` decision.
8. Fixed after review: the phone "Filters" button has `aria-label="Filters, N active"` when filters are set. Still open: facet counts in the sheet are whole-collection, so "Common 1176" sits next to "View 36".
9. Unreachable branches behind `DataGate`: `CardHero` `card === undefined` placeholder and `CardPage` `data !== undefined` guard; `CardPage` memoises `copies` with a second full scan per card id on top of `useCardById` (fine at 2,138 rows, but one pass would give both).
10. Inconsistent recent-search capture: `SearchBox` records on blur and submit, `QuickSearch` only on submit; `RecentSearches` clears via `useStore.setState` because the frozen store has no `clearRecentSearches` action (inherited).
11. Tests: e2e asserts dataset magic numbers ("36 cards", "238", "19 cards") that break on any data change; no e2e for the error state, phone swipe or reduced motion; `.claude/rules/testing.md` still says port 4173 while `test/playwright.config.ts` uses 4184 (not editable by this build).
12. Not in this build: README (assignment deliverable), PWA/offline (settled 2.14), the GitHub Actions deploy workflow (2.15; a 7-day preview channel is deployed, see header); `document.title` is only set on the detail page.
13. A hard navigation (reload / URL entry) within ~200 ms of a Back leaves an unhandled "Transition was skipped" rejection from the router's view transition in the console (`main.tsx` `defaultViewTransition: true`). Only reachable by racing the address bar against a running transition; nothing to do in app code short of a `unhandledrejection` filter, so cosmetic.
